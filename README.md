# AI Dev Squad — فريق تطوير متعدد الوكلاء

منصة تربط مستودع GitHub بمجموعة وكلاء ذكاء اصطناعي (مدير مشروع، معماري، مبرمج، مجلس مراجعة):
تُحلَّل مهمة برمجية بلغة طبيعية، تُقسَّم إلى مهام، وتُنفَّذ كـ **تغييرات مقترحة (Change Set)** على فرع عمل —
ثم تُعرض على مجلس مراجعة قبل أي دفع.

> هذا الملف يصف **ما هو منفَّذ فعلاً** في هذا المستودع. أي ميزة غير مذكورة هنا = غير موجودة.

## ما يعمل فعلياً

### الاتصال والفحص
- ربط المستودع عبر GitHub Personal Access Token، مع تحقق من الصلاحيات قبل أي عملية.
- فحص بنية المستودع وقراءة الملفات عبر GitHub REST API (بلا clone محلي).

### طبقة مزوّدين النماذج
- مزوّدون مدعومون: Gemini، OpenRouter، Groq، Mistral، Hugging Face — التجريد خلف واجهة واحدة.
- **وضع «المجاني فقط» مفروض برمجياً**: عند تفعيله لا يُختار إلا نموذج يضمن المزوّد مجانيته
  (لاحقة `:free`). النماذج ذات التكلفة غير المعروفة تُستبعد — بلا fallback مدفوع صامت.

### خط الأنابيب متعدد الوكلاء
- **مدير المشروع** يحلل المهمة ويوزعها ويقرر الاحتياج من الوكلاء.
- **المعماري** يحدد الملفات المعنية والمخاطر قبل أي تعديل.
- **المبرمج** ينفذ التغييرات كسلسلة ملفات مقترحة عبر GitHub Contents API.
- **مجلس المراجعة** يراجع الفروق ويصدر البوابة: `APPROVED` / `CHANGES_REQUESTED` / `FAILED`.

### الأمان
- الكتابة على **الفروع المحمية** (main / master / develop / production / release / staging) مرفوضة برمجياً — لا استثناءات.
- حواجز مسارات مشتركة في `src/lib/safety.ts`: منع داخل `.git` و`.github/workflows` و`.env*` و`node_modules`،
  وملفات الاعتماد (`.pem` / `.key` / ...)، والملفات الثنائية و`.lock`، والمسارات المطلقة والعبور (`..`).
- **إخفاء الأسرار في كل مكان**: كل قيمة تشبه مفتاحاً (`ghp_` / `github_pat_` / `AIza` / `sk-` / `gsk_` / `hf_`)
  تُستبدل بـ `[redacted]` قبل أن تصل لأي رسالة أو خطأ أو سجل، والمفاتيح تُعرض مقنّعة فقط (`ghp_••••••4f2a`).
- **اختبارات وحدة حقيقية** لهذه الضوابط في `tests/safety.test.ts` تُشغَّل بـ `bun test`.

## ما لا يفعله هذا المشروع (بصراحة)

- **لا يوجد Sandbox ولا تنفيذ للأكواد.** المنصة لا تشغّل `npm test` ولا `npm run build` ولا أي أمر داخل
  المستودع الهدف. بوابة الاعتماد تعتمد على **مراجعة AI للفروق فقط**.
- **مفاتيح المستخدم تُخزَّن في `localStorage` بالمتصفح** (المفتاح `aidevteam.user-secrets.v1`):
  أي سكربت XSS في نفس النطاق يستطيع قراءتها. تُنقل مع الطلب فقط وتُستهلك داخل `AsyncLocalStorage`
  على الخادم (بلا تسجيل ولا تخزين خادمي)، لكن التخزين في المتصفح يبقى **حداً معروفاً غير معالج**.
- **حالات التحقق صريحة وصدوقة**: بجانب البوابة ترى دائماً
  `tests: not_run · build: not_run · security: ai_review_only` —
  هذه ليست إنجازات؛ إنها إقرار بأن هذه الفحوصات لم تُنفَّذ.
- لا هجرات قواعد بيانات، ولا عمليات git ثنائية الاتجاه (clone/push محلي): كل شيء عبر REST API.

## التشغيل محلياً

```bash
bun install
bun run dev      # التطوير
bun run verify   # lint + typecheck + test
```

## البنية المختصرة

```
src/lib/safety.ts            # الضوابط الأمنية المشتركة (اختبارات: tests/safety.test.ts)
src/lib/connection.*         # ربط المستودع والتحقق من الصلاحيات
src/lib/inspection.*         # فحص بنية المستودع
src/lib/workspace.tsx        # منسّق الوكلاء وخط الأنابيب
src/lib/coder.server.ts      # تنفيذ التغييرات المقترحة
src/lib/review.server.ts     # مجلس المراجعة + حالات التحقق
src/lib/git.server.ts        # عمليات GitHub API المؤمّنة
src/lib/model-picker.ts      # اختيار النماذج + سياسة «المجاني فقط»
```

## حدود المسؤولية

المنصة تقترح وتنفذ تغييرات نصية عبر API وتعرضها للمراجعة. **القرار النهائي بالدمج يبقى للإنسان**،
ولا يُقرأ أي شيء هنا كضمان جودة تشغيلية — لأن لا شيء يُشغَّل.
